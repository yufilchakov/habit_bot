# LLM-советник в трекере привычек

Telegram-бот, который помогает формировать привычки с помощью персонализированных советов от LLM (YandexGPT). Анализирует историю выполнения привычек и генерирует тёплые мотивирующие сообщения.

## Возможности

- Добавление привычек (просто напишите название)
- Отметка выполнения: `+ привычка`
- Получение мотивационного совета на основе последних 7 дней (команда `совет`)
- Ответы на вопросы в роли поддерживающего тренера
- In-memory хранение (Redis опционален)
- Гибкая архитектура для замены LLM (YandexGPT, OpenAI, локальные модели)

## Технологии

- **Python 3.12+**
- **FastAPI** – веб-фреймворк для обработки вебхуков
- **YandexGPT** – языковая модель через REST API
- **Redis** – опционально, для персистентности (по умолчанию in-memory)
- **Telegram Bot API** – вебхуки или long polling
- **Poetry** – управление зависимостями
- **Pytest** – тестирование (покрытие >70%)
- **Black, Ruff** – форматирование и линтинг
- **Docker** – контейнеризация
- **Makefile** – удобные команды для разработки

## Установка и запуск (локально)

### Предварительные требования

- Python 3.12 или 3.13
- Poetry (установка: `pip install poetry`)

### Шаги

1. **Клонировать репозиторий**

   ```bash
   git clone https://github.com/Yufilchakov/habit-bot.git
   cd habit-bot

### Установить зависимости через Poetry

poetry install (будут установлены и основные, и dev-пакеты)

Создать файл .env (скопировать .env.example и заполнить)

## Обязательные переменные:

TELEGRAM_TOKEN=ваш_токен_бота 

YANDEXGPT_FOLDER_ID=ваш_folder_id

YANDEXGPT_API_KEY=ваш_api_ключ

REDIS_URL=redis://localhost:6379 

LLM_MODEL=yandexgpt-lite

LLM_TEMPERATURE=0.7

LLM_MAX_TOKENS=200

Запустить Redis (если нужен)
docker-compose up -d или используйте make docker-up. 

Если не нужен – бот будет использовать in-memory хранилище (все данные потеряются при перезапуске).

Запустить сервер разработки

poetry run uvicorn src.main:app --reload --port 8000

Настроить вебхук для Telegram (локально – через туннель)

Запустите ngrok http 8000 (или другой туннель, xTunnel, Tuna, cloudflared)

Получите публичный HTTPS-адрес вида https://xxxx.ngrok.io

Установите вебхук через браузер:

https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://xxxx.ngrok.io/webhook
Проверьте бота: отправьте /start

Альтернативно можно использовать long polling (без вебхуков): замените main.py на версию с Application.run_polling() (в проекте есть пример).


## Тестирование

Запустить все тесты:
poetry run pytest -v
С покрытием:

poetry run pytest --cov=src --cov-report=html

Покрытие кода не менее 70% (цель – 80%).

make dev – запуск сервера в режиме разработки (перезагрузка при изменении)

make test-cov – тесты с отчётом о покрытии

make lint – проверка кода линтерами (ruff, mypy)

## Архитектура и ключевые решения:
Чистая архитектура: handlers, services, repositories – разделение ответственности.

Dependency Injection через FastAPI Depends (или lru_cache для синглтонов).

Абстракция LLM: легко заменить YandexGPT на OpenAI или локальную модель (через класс LLMService).

In-memory репозиторий используется по умолчанию, Redis подключается без изменения кода (через переменную REDIS_URL).

Асинхронность: FastAPI и httpx для неблокирующих вызовов LLM.

Тестирование: моки для LLM и репозитория (fakeredis), изоляция тестов.
